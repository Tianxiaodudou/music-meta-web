# 音乐数据刮削（Music Meta Scraper）

fnOS 原生应用，为本地音乐库批量补齐元数据的专业工具。支持 flac / mp3 / ogg / ape 等格式，自动从多个数据源检索并写入封面、歌手、年份、专辑、流派、唱片公司、语言、曲目号与内嵌歌词等标签。

## 功能介绍

- **智能识别匹配**：不猜「哪个是歌手、哪个是歌名」——把文件名拆成候选关键词直接搜索，再用搜索结果反推歌名与歌手（要求结果的歌名与歌手都出现在文件名中，顺序无关），从多个数据源检索并写入完整元数据；也支持 AcoustID 音频指纹识别（指纹工具 `fpcalc` 已随安装包内置，无需在系统里另装，只需自行申请免费的 AcoustID Key）。
- **文件名多格式自适应**：自动去扩展名、音轨号（`01.` / `Track01`）、音质与来源噪音标签（`[320K]` / `(Hi-Res)` / `官方版` / `MV`），按分隔符优先级（` - ` > `–` > `—` > `-` > `_` > `|`）拆出整串/左右段候选，书名号与括号内的内容也会单独作为候选；`歌手 - 歌名` 与 `歌名 - 歌手` 两种命名都能识别，无需反序补搜。
- **手动刮削窗口**：队列里任意一首点「手动刮削」即现场重刮并缓存候选；窗口上方是本地音频播放器与内嵌歌词同步高亮（点歌词可跳转），下方按「生效字段」逐行对照「原有 / 候选」，点「手动刮削」下拉选一个候选值再点「写入」即可单字段覆盖写入，另有内嵌歌词与候选歌词对比框。
- **自动化流程**：候选通过「文件名反推校验」即自动写入并永久记忆（按文件大小 + 内容哈希），后续扫描/刮削自动跳过，避免重复请求；未通过校验的进入人工辅助队列。打分只用于候选排序，不再决定是否命中。
- **单队列 + 状态过滤器**：全部歌曲合并成一个队列，顶部按状态筛选（全部 / 自动写入 / 待刮削 / 已人工 / 待人工 / 跳过 / 错误），过滤器右侧的「ⓘ 标签说明」会逐个解释每个标签是什么意思；每张卡片的状态标签可点击，手动把这首歌指定为任意状态。
- **处理记录（永久记忆）覆盖「已人工 / 错误 / 跳过」三种标签**：这三种标签都会记进处理记录，重新扫描时按记录还原成对应标签，即使文件被改名或搬家也能按大小 + 哈希认出来（哈希只对人工逐条的「已人工」计算，批量产生的错误/跳过只记大小）；改成别的状态（例如「待刮削」）时记录会跟着清掉 —— 状态只认当前生效的那一份。设置页可「导出到本机 / 导入记录文件 / 清除记录」：**清除记录**只清记录、不动音乐文件，并把这三种标签的文件放回「待刮削」（有二次确认，先导出就能随时导回来）；导入时按路径合并，并会把队列里命中的任务改成记录里的标签。
- **「已人工」只由人工逐条操作产生**：在队列里手动指定为「已人工」，或在手动刮削窗口逐条写字段，都会永久记住这首歌，**清空任务列表或删除任务后重新扫描仍是「已人工」**，绝不会被再次刮削；只有人工把它指定成别的状态它才会离开这个标签。批量处理与自动刮削写入的文件记为「自动写入」，不产生这个标签；打开「启用真实写入」后点一次「开始刮削」，会把之前在学习模式下匹配好、还没写进文件的歌一并写掉。
- **生效字段**：设置页（右上角 ⚙）勾选生效字段，默认只保留 歌名 / 歌手 / 封面图 / 歌词；未勾选的字段在任何界面都不显示、也不会被写入文件。
- **多数据源插件化**：QQ 音乐 / 网易云 / 酷狗 / 酷我 / LRC Lib / TheAudioDB / iTunes 等数据源即插即用，内置全局限速与随机间隔防止风控，同曲目本地缓存零重复请求。
- **数据安全**：支持真实写入开关（默认仅学习预览）、目录级写保护与中文错误提示，任务与标签可随时复核、移回或删除。

## 数据源插件

本应用安装包**不内置任何数据源**，所有数据源均为单文件插件（`.py`），按需下载、复制即用、随用随换。

- **下载**：本仓库 [data-source-plugins/](data-source-plugins/) 目录即为全部官方插件源码，也可从每个 [GitHub Release](https://github.com/Tianxiaodudou/music-meta-web/releases) 的源码附件中获取。常用插件：
  `qqmusic.py`（QQ 音乐，含音频指纹）、`netease.py`（网易云）、`kugou.py`（酷狗）、`kuwo.py`（酷我）、`lrclib.py`（LRC Lib 歌词）、`theaudiodb.py`（TheAudioDB 欧美/日韩）、`itunes.py`（iTunes 示例）。
- **使用三步**：
  1. 下载需要的 `.py`（在电脑上下载的话，记得把它传到 NAS 上），复制到 NAS 上任意一个目录，例如 `/vol2/1000/plugins`；然后打开应用 → 配置页 →「**数据源插件目录**」，填上**这个目录**——**插件放在哪个目录，这里就填哪个目录，两者必须是同一个**（安装向导里问的「数据源插件目录」也是填它；留空则用应用数据目录 `plugins/`）；
  2. 在 fnOS 应用中心**重启**本应用；
  3. 回到应用配置页勾选数据源即可（可多选，候选自动合并，每源最多 10 条）。

> 每个文件都是独立单文件插件，可单独复制，全部**免配置**（无需注册、无需密钥，qqmusic 的音频指纹识别需自行申请 AcoustID Key，指纹工具已内置）。欢迎任何人改进插件或开发新数据源并提交 PR。

## 构建与发布

**打包只在 GitHub 上进行**：本地不打包、也不在本地下载依赖包。流程是推一个与 `manifest` 中 `version` 一致的 tag（如 `v1.4.8`），由 [GitHub Actions](.github/workflows/build-release.yml) 完成全部工作：

1. 按 `app/server/requirements.lock.txt` 拉取运行期依赖的 wheel（cp311，x86_64 与 aarch64 两种架构）；
2. 校验轮子集合 —— 逐个依赖 × 逐个架构判定可满足性，并核对编译扩展的 ELF 架构；
3. 建 venv、`--no-index` 离线装一遍、import，并用这套内置依赖跑应用自身的测试（该测试用 ffmpeg 造样本音频，CI 里显式安装 ffmpeg）；
4. 把 `CHANGELOG` 当前版本段落注入 `manifest.changelog`（应用中心的更新说明）；
5. 用官方 `fnpack` 打包，然后**回读成品**确认依赖真的在包内、双架构齐备、字段正确；
6. 发布 Release（正文自动取自 `CHANGELOG.md`）。

### 依赖内置的机制

运行期依赖以 wheel 形式打进 fpk（`app/server/vendor/wheels/`，该目录由 CI 生成、不入版本库）。客户端 `cmd/main` 启动时用

```
pip install --no-index --find-links <包内轮子> -r requirements.lock.txt
```

安装 —— `--no-index` 是显式断网开关，不会回落到网络索引，所以**安装后立即可用，不受网络状况影响**。同一个 fpk 同时内置 x86_64 与 aarch64 的轮子（纯 Python 包共用一份，编译扩展 `pydantic_core` 两种各一份），pip 在目标机按当前架构自动挑选，因此一个安装包通吃两种架构。

改依赖版本只需改 `app/server/requirements.lock.txt`：CI 会重新拉轮子并重新验证；若某个架构没有对应轮子，CI 会直接失败而不会带病发布。
