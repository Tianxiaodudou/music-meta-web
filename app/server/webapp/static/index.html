风控设置

数据源都是第三方公开接口，请求过密会被限流甚至临时封禁。下面每一项都影响「速度 ↔ 风险」的取舍： 默认值偏保守，批量刮几百首建议保持默认；只在明确知道自己在做什么时再调低间隔 / 调高并发。

请求间隔（秒）0.3
同一数据源两次网络请求之间的最小间隔（带随机抖动）。 调大：更安全、更慢；调小：更快、更容易触发风控。建议 ≥ 0.3。
并发数1
同时刮削几个文件（后台 worker 数）。1 = 一首一首来，最稳； 调大能提速，但请求会成倍变密，且同一首歌的日志会交错。建议 1～2。
每源候选数10
每个数据源为每首歌返回多少条候选（手动刮削窗口里下拉能看到的就是这些）。 只影响「拿到多少候选」，不额外多发请求；但条数越多，本地排序/展示越慢。默认 10。
请求超时（秒）15
单次网络请求最多等多久。调太短会把慢响应直接算作失败（然后重试，反而更费力）； 调大遇到卡住的接口会等更久。默认 15 秒。
适用范围：支持该参数的插件（如 qqmusic）；其它插件用自身内置默认值（15 秒）。
失败重试次数2
一次请求失败（超时 / 风控 / 5xx）后自动重试几次，重试间隔按 2 倍指数退避。 0 = 不重试（更快但更容易漏掉网络抖动的歌）。默认 2。
适用范围：同「请求超时」，只对支持该参数的插件生效（如 qqmusic）。
单次运行上限（首）0
每点一次「开始刮削」最多处理多少首，处理完自动停下（任务保留在队列，下次继续）。 0 = 不限（一次跑完整个队列）。大批量建议设 200～500，分段跑更不容易被风控，也方便中途检查效果。
每处理几首暂停一次0
每刮完这么多首就整体停一会儿再继续。0 = 不暂停。 大规模刮削（几千首）时，持续不断的请求最容易触发风控； 设成 50～100 首歇一次，能明显降低被限流的概率，代价只是整体慢一点。
这一项是应用层控制，对所有数据源都生效。
暂停时长（秒）5
上面那次暂停休息多久。太短起不到作用，太长会拖慢整体进度； 一般 5～30 秒即可（配合「每 100 首」大概相当于每首多花 0.05～0.3 秒）。

目录设置

路径都要写容器/系统里的绝对路径（以 /vol… 开头）。 真正的读写权限还要在「应用中心 → 音乐数据刮削 → 设置 → 授权目录」里授权，否则会出现只读或无权访问。

音乐库目录刮削对象所在目录（必填）
扫描这里的所有音频文件（flac/mp3/ogg/ape）。授权后本应用才会读写其中的标签。
数据源插件目录存放 *.py 数据源插件
把 qqmusic.py / netease.py 等单文件插件放这里，重启应用后在「元数据源」里勾选。
元数据缓存目录歌曲/专辑/封面/歌词的本地缓存
